# Requirements Document

## Project Description (Input)
wiki のホーム画面 v3。v2（home-page-widgets）で /home 上部に4ウィジェット（検索・最近更新・ブックマーク・書きかけ(WIP)、ログイン利用者のみ、固定順・個別エラー境界、react-error-boundary、下部にお知らせ＋動作環境の要件表）を実装・デプロイ済み。お知らせは管理画面の customize:homeNotice 設定、`/home-notice` からの初回移行あり。v3 では以下を追加する: (1) 新ウィジェット3種 — Classroom最新投稿（外部 classroom-sync-agent が Classroom のお知らせ/資料を GROWI ページとして同期しており、その同期済みページのうち最近のものを一覧表示。同期先パスは設定可能にする想定）、ピン留め・よく見るページ（管理者がピン留めしたページリンク＋利用者本人のよく見る/最近見たページ）、スケジュール/直近の更新フィード（アクティビティやスケジュール系の直近イベントのフィード）。(2) 管理者によるウィジェット設定 — サイト共通のデフォルト（各ウィジェットの表示/非表示・並び順）を管理画面から設定でき、さらに各利用者が自分の /home だけそのデフォルトを上書き（並べ替え・非表示）できる。サイト共通設定は管理画面、個人別上書きは /home 上または /me で行う想定。個人別設定はユーザー別に永続化する。(3) /home ページ自体とウィジェットカードの見た目の作り込み（ヒーロー領域、カードデザイン、レスポンシブなグリッドレイアウト）。v2 で確立した「/nas 型の独立した編集不可ページ」「ログイン後の既定遷移先」「動作環境の要件表」「サイドバーのナビアイコン」という性質は維持。lite UI ティア向けのネイティブ /home 表示は v3 でもスコープ外でよい。

## Introduction

物理部 wiki の `/home`（v2 実装済み）を拡張する。上部のウィジェットエリアに新しく3種類のウィジェット（Classroom最新投稿、ピン留めページ、お知らせ・予定フィード）を追加し、これまで固定だったウィジェットの表示/非表示と並び順を、管理者がサイト共通の初期状態として設定でき、各利用者が自分の `/home` だけ上書きできるようにする。あわせて `/home` 画面とウィジェットカードの見た目を作り込む。v2 で確立した性質（`/nas` 型の独立した編集不可ページ、ログイン後の既定遷移先、下部のお知らせと動作環境の要件表、サイドバーのナビアイコン、お知らせの管理画面設定）は維持する。

「よく見る/最近見たページ」（利用者本人の閲覧履歴に基づく一覧）は v3 のスコープから外し、ピン留めページウィジェットは管理者がピン留めしたページのみを扱う（利用者個人のよく参照するページは、v2 のブックマークウィジェットが引き続き担う）。

## Boundary Context

- **In scope**:
  - ウィジェットエリアを、v2 の4ウィジェットに v3 の3ウィジェットを加えた計7種類で構成し、v2 と同じく個々のウィジェットの障害を他へ波及させない
  - Classroom最新投稿ウィジェット：外部同期で作られた Classroom 由来ページのうち最近のものを一覧表示。取得元パスは管理者が設定できる
  - ピン留めページウィジェット：管理者が管理画面で維持する「重要ページ」リンクの一覧を表示
  - お知らせ・予定フィードウィジェット：部の今後のイベント、利用者本人宛の直近の通知、利用者本人の未回答の出欠確認、をまとめて表示
  - 管理者によるウィジェット設定：各ウィジェットの表示/非表示・並び順の「サイト共通の初期状態」と、一部ウィジェットの個別オプション（ピン留めリンクの一覧、Classroom の取得元パス、リスト系ウィジェットの表示件数）を管理画面で設定
  - 利用者による個人別ウィジェット設定：各利用者が自分の `/home` だけ、7ウィジェットの表示/非表示と並び順を変更でき、その内容は利用者ごとに保存されて次回以降も反映される
  - `/home` 画面とウィジェットカードの見た目：ヒーロー領域、カードデザイン、画面幅に応じて折り返すグリッドレイアウト
  - v2 の性質の維持

- **Out of scope**:
  - 利用者本人の閲覧履歴・閲覧回数に基づく「よく見る/最近見たページ」一覧（v3 では実装しない）
  - Classroom 側との直接連携（Classroom API 呼び出し、認可、同期処理そのもの）。本機能は外部同期が作った GROWI ページを読むだけで、同期の設定・実行には関与しない
  - 外部同期エージェントが書き込むパスそのものの変更（エージェント側の設定であり本機能の責務外。本機能で設定するのは「ウィジェットがどのパス配下を読むか」）
  - 出欠確認そのものの仕組み（イベントの管理、回答の収集・集計）。フィードウィジェットは既存の未回答判定を参照して案内を出すのみ
  - ゲスト（未ログイン利用者）向けのウィジェット表示。v2 と同じくウィジェットエリアはログイン利用者にのみ表示する
  - 下部のお知らせセクションと動作環境の要件表を、ウィジェット設定（表示/非表示・並び替え）の対象に含めること。これらは引き続き固定のページセクションとする
  - トップページ（`/`）の置き換え、lite UI ティア向けのネイティブな `/home` 表示
  - 管理者が新しい種類のウィジェットを実行時に定義・追加する仕組み（ウィジェットの種類はコード上で固定）

- **Adjacent expectations**:
  - 外部の Classroom 同期エージェントが、既知のパス配下に Classroom のお知らせを GROWI ページとして継続的に作成していること。エージェントが停止していれば当該ウィジェットは新しい項目を表示できない
  - 部のイベント情報が、既存の運用どおり所定のイベントページに記載されていること
  - 利用者本人宛の通知、未回答の出欠確認の判定は、既存の機能の結果をそのまま利用する（本機能はこれらを新規に定義しない）
  - ページの閲覧権限(ACL)によるフィルタリング、検索・最近更新・ブックマーク・書きかけ状態の仕組みは、v2 と同じく既存機能をそのまま利用する

## Requirements

### Requirement 1: ウィジェットエリアの構成と障害分離

**Objective:** As a wiki 利用者, I want ホーム上部のウィジェットエリアが v2 の4種類に v3 の3種類を加えた構成で、1つのウィジェットの不具合が他に波及しない, so that 追加ウィジェットがあっても /home 全体が安定して使える

#### Acceptance Criteria
1. While 利用者がログインしている場合, the Home Page shall ウィジェットエリアに、検索・最近更新・ブックマーク・書きかけ・Classroom最新投稿・ピン留めページ・お知らせ予定フィードの計7種類のウィジェットを表示対象として扱う。
2. If 個々のウィジェットの取得または描画に失敗した場合, then the Home Page shall 該当ウィジェットのみをエラー表示にとどめ、他のウィジェットおよびページ全体の表示を継続する。
3. When ある利用者に対して表示対象のウィジェットが1つも無い場合, the Home Page shall ウィジェットエリアを空のまま（またはウィジェットが無い旨を示したうえで）、ページ全体の表示を継続する。
4. The Home Page shall v3 において、ウィジェットの種類を上記7種類に固定し、利用者や管理者が新しい種類のウィジェットを実行時に定義・追加する機能を提供しない。

### Requirement 2: Classroom最新投稿ウィジェット

**Objective:** As a ログイン済み利用者, I want Classroom のお知らせが GROWI に取り込まれたものを /home で最近のものから確認したい, so that Classroom を別途見に行かなくても最新のお知らせを把握できる

#### Acceptance Criteria
1. While 利用者がログインしている場合, the Home Page shall 外部同期によって作られた Classroom 由来ページのうち、取得元パス配下にあるものを更新日時の新しい順に一定件数表示するウィジェットを表示する。
2. The Home Page shall Classroom最新投稿一覧に、利用者が閲覧権限を持たないページを含めない。
3. When 利用者が一覧内の項目をクリックした場合, the Home Page shall 該当ページへ遷移する。
4. If 取得元パス配下に該当ページが1件も存在しない場合, then the Home Page shall その旨を示す空状態のメッセージを表示する。
5. Where 管理者が Classroom の取得元パスを設定している場合, the Home Page shall そのパス配下を対象とし、未設定の場合は既定の取得元パスを対象とする。

### Requirement 3: ピン留めページウィジェット

**Objective:** As a wiki 管理者, I want 部員に見てほしい重要ページへのリンクを /home に固定表示したい, so that よく参照すべきページを全員がすぐ開ける

#### Acceptance Criteria
1. The Home Page shall 管理者が管理画面で維持する「ピン留めページ」の一覧を、管理者が指定した順序で表示するウィジェットを提供する。
2. When 管理者がピン留めページの一覧（対象ページと任意の表示名、並び順）を更新して保存した場合, the Home Page shall 以降のホームページ表示に更新後の一覧を反映する。
3. When 利用者が一覧内の項目をクリックした場合, the Home Page shall 該当ページへ遷移する。
4. If ピン留めページが1件も設定されていない場合, then the Home Page shall 管理者に対してのみ設定を促す案内を表示し、管理者以外の利用者にはこのウィジェットを表示対象から外す。
5. If ピン留めページとして指定されたページが存在しない、または利用者が閲覧権限を持たない場合, then the Home Page shall その項目を一覧に表示しない。

### Requirement 4: お知らせ・予定フィードウィジェット

**Objective:** As a ログイン済み利用者, I want 部の今後の予定・自分宛の通知・未回答の出欠確認を /home で一目で把握したい, so that 見落としを減らし必要な対応にすぐ移れる

#### Acceptance Criteria
1. While 利用者がログインしている場合, the Home Page shall 部の今後のイベントを、開催日の近い順に一定件数表示する。
2. While 利用者がログインしている場合, the Home Page shall 当該利用者宛の直近の通知を、新しい順に一定件数表示する。
3. If 当該利用者に未回答の出欠確認がある場合, then the Home Page shall その旨と回答先への導線を表示する。
4. When 利用者がフィード内の項目（イベント・通知・出欠確認の案内）をクリックした場合, the Home Page shall 対応するページまたは回答画面へ遷移する。
5. If 表示できるイベント・通知・未回答の出欠確認がいずれも無い場合, then the Home Page shall その旨を示す空状態のメッセージを表示する。

### Requirement 5: 管理者によるサイト共通のウィジェット設定

**Objective:** As a wiki 管理者, I want すべての利用者に共通して適用されるウィジェットの初期状態を管理画面で決めたい, so that /home が部の運用に合った既定の並びで全員に見える

#### Acceptance Criteria
1. The Home Page shall 7種類の各ウィジェットについて、サイト共通の「初期表示状態（表示/非表示）」と「初期の並び順」を、管理者が管理画面で設定できるようにする。
2. Where 管理者が特定のウィジェットにオプション（ピン留めページの一覧、Classroom の取得元パス、リスト系ウィジェットの表示件数）を持たせている場合, the Home Page shall そのオプションを管理画面で設定でき、当該ウィジェットの表示に反映する。
3. When 管理者がサイト共通のウィジェット設定を更新して保存した場合, the Home Page shall 個人別に上書きしていない利用者の /home に、以降その設定を反映する。
4. The Home Page shall 管理者がサイト共通設定で「非表示」にしたウィジェットを、利用者の初期状態としては非表示にしつつ、利用者が自分で表示に戻すことは妨げない。
5. If 管理者がサイト共通のウィジェット設定を一度も保存していない場合, then the Home Page shall あらかじめ定めた既定の並びと表示状態を全利用者に適用する。

### Requirement 6: 利用者による個人別のウィジェット設定

**Objective:** As a ログイン済み利用者, I want 自分の /home のウィジェットの並びと表示/非表示を自分で調整したい, so that 自分の使い方に合ったホーム画面にできる

#### Acceptance Criteria
1. While 利用者がログインしている場合, the Home Page shall 当該利用者が自分の /home 上で、7種類の各ウィジェットの表示/非表示と並び順を変更できる手段を提供する。
2. When 利用者が自分のウィジェットの並び・表示状態を変更した場合, the Home Page shall その内容を当該利用者ごとに保存し、以降の /home 表示に反映する。
3. While 利用者が個人別の設定を持っている場合, the Home Page shall サイト共通設定より当該利用者の個人別設定を優先して /home を表示する。
4. When 利用者が自分の個人別設定を「初期状態に戻す」操作をした場合, the Home Page shall 当該利用者の /home をサイト共通設定に従った状態に戻す。
5. If 利用者の個人別設定が特定のウィジェットについて表示/非表示を明示していない場合, then the Home Page shall そのウィジェットについてはサイト共通設定の表示状態を適用する。

### Requirement 7: /home 画面とウィジェットカードの見た目

**Objective:** As a wiki 利用者, I want /home が単なるリストの寄せ集めではなく整った画面に見えてほしい, so that ホームとして開いたときに使いやすく感じられる

#### Acceptance Criteria
1. The Home Page shall ページ上部に、wiki 名や役割を示すヒーロー領域を表示する。
2. The Home Page shall 各ウィジェットを、見出しと内容が視認できるカードとして表示する。
3. While 画面幅が広い場合, the Home Page shall 複数のウィジェットカードを横に並べたグリッドで表示し、While 画面幅が狭い場合, the Home Page shall カードを1列に折り返して表示する。
4. When 表示対象のウィジェット数が変化した場合（0個から複数個まで）, the Home Page shall レイアウトを崩さずに表示する。

### Requirement 8: ゲストアクセス時の表示

**Objective:** As a 匿名(ゲスト)閲覧者, I want ホーム画面の個人に依存しない情報は見られるようにしてほしい, so that ログインしなくても wiki の基本情報を確認できる

#### Acceptance Criteria
1. While 匿名ゲストが既存のアクセス制御上ホームページを閲覧できる場合, the Home Page shall v2 と同様にお知らせと動作環境の要件表を表示する。
2. The Home Page shall ウィジェットエリア（v3 で追加したものを含む全7種類）を、ログインしていない利用者には表示しない。

### Requirement 9: v2 からの継続性

**Objective:** As a wiki 利用者, I want v2 で提供されていたホーム画面の性質がそのまま使える, so that v3 への移行によって既存の使い方が壊れない

#### Acceptance Criteria
1. The Home Page shall 引き続き `/nas` と同様の、独立した閲覧専用（wiki ページとして編集不可）ページとして提供される。
2. The Home Page shall 引き続きサイドバーのナビゲーションからアクセスできるアイコンを提供する。
3. The Home Page shall 引き続き、ログイン後に遷移先が指定されていない場合の既定の遷移先として機能する。
4. The Home Page shall 引き続き、下部に管理画面で編集できるお知らせ（設定が空欄なら管理者にのみ設定を促す案内、管理者以外には非表示）と、動作環境の最低/推奨要件の表を表示する。
